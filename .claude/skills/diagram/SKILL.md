# 図を描く

図の価値は「何を・誰に伝えるか」に合った図種を選べたかでほぼ決まる。描き始める前に図種を選び、1枚の図には1つの問いだけを答えさせる。

## 手順

1. **問いを1文にする。** 「この図を見た読み手は何に答えられるようになるか」を書き出す（例:「注文確定時、どのコンポーネントがどの順で呼ばれるか」）。複数の問いがあるなら図を分ける
2. **読み手を決める。** 顧客・PM向けなら機能範囲や業務の流れまで、開発者向けならクラス・メッセージの粒度まで描く
3. **下の選定表で図種を決め、選んだ理由を1行で添える。** 依頼者が図種を指定していても、問いに合わない場合は代案を示す
4. **図種別の手順に沿って描く。**
5. **図の後に補足を最大3行書く。** 前提、省いたもの、図だけでは読み取れない制約。図に書いてあることを文章で繰り返さない

## 図種の選定

| 伝えたいこと（問い） | 図種 | Mermaid |
|---|---|---|
| システムで誰が何をできるか・スコープ | ユースケース図 | `flowchart`（アクター→機能）で代用 |
| 業務・処理の流れ、条件分岐、並行処理 | アクティビティ図 | `flowchart` |
| 要素間のやり取りの**時間順**（API連携、障害時の挙動） | シーケンス図 | `sequenceDiagram` |
| ライフサイクル・ステータスの遷移とトリガー | ステートマシン図 | `stateDiagram-v2` |
| クラス・型の属性と関係（継承・関連・依存） | クラス図 | `classDiagram` |
| テーブルとリレーション | ER図 | `erDiagram` |
| モジュール・サービスの依存とインターフェース | コンポーネント図 | `flowchart` + `subgraph` |
| サーバー・ネットワーク・デプロイ先の物理配置 | 配置図 | `flowchart` + `subgraph`（境界=VPC/ホスト等） |
| 大きなシステムの論理的なグルーピング | パッケージ図 | `flowchart` + `subgraph` |
| スケジュール・期間 | ガントチャート | `gantt` |

迷ったときの判定:
- 「順番」が主役ならシーケンス図、「分岐」が主役ならアクティビティ図
- 「いま何の状態か」を問うならステートマシン図。フロー図に状態を混ぜない
- 構造（静的）と振る舞い（動的）を1枚に混ぜない。両方必要なら2枚描く

## 図種別の描き方

- **ユースケース図**: アクターを定義 → ユースケースを動詞句で洗い出す → include/extend など関係を書く。システム境界を `subgraph` で示す
- **アクティビティ図**: 開始・終了を置く → 処理を箱にする → 分岐は菱形で、条件をエッジのラベルに書く。異常系の行き先を省かない
- **シーケンス図**: 参加者を左から呼び出し順に並べる → メッセージを時系列で書く → 正常系と異常系は `alt` で分けるか図を分ける。並行処理は `par`、繰り返しは `loop`
- **ステートマシン図**: 状態を列挙 → 遷移ごとにトリガー（イベント/条件）をラベルにする → 初期状態と終了状態を明示する。どこからも遷移しない状態・抜け出せない状態がないか確認する
- **クラス図 / ER図**: 主要な要素を3〜7個に絞る → 属性・操作は問いに関係するものだけ書く → 関係は種類（継承/集約/依存、多重度）を書き分ける
- **コンポーネント図 / 配置図**: ノードを定義 → 接続にプロトコルや向きをラベルで書く → アクセス制御などの境界を `subgraph` で表す

## 描画ルール

- **記法**: 既定は Mermaid（GitHub・Qiita・Notion等でそのまま描画される）。依頼者がPlantUMLを指定した場合や、Mermaidにない図種（タイミング図、厳密なユースケース図・配置図）が必要な場合は PlantUML。プレーンテキストしか表示できない場所ではASCII
- **規模**: 1枚あたりノード15個程度まで。超えるなら全体図と詳細図に分割する
- **ラベル**: ノード名はコード上・仕様上の実名を使う。存在を確認していない名前を作らない。推測で補った要素は「（推定）」と書く
- **矢印**: 向きと意味（呼び出し/データの流れ/依存）を1枚の中で統一する。意味が混在する場合は線種かラベルで区別する
- **Mermaidの構文**: ラベルに `()` `:` `"` などの記号を含むときは `A["ラベル(説明)"]` のように引用符で囲む。日本語のノードIDは使わず、IDは英数字・ラベルは日本語にする
- **保存**: ファイルに残す場合は `.md` 内のコードブロックか `.mmd` / `.puml` にする。図をテキストで持つことで差分レビューやバージョン管理ができる

## アンチパターン

- 何でもフローチャートで描く（時間順はシーケンス図、状態はステートマシン図の方が読み違いが少ない）
- 1枚に構造・振る舞い・インフラを全部載せる
- 全クラス・全カラムを網羅して、問いに関係する部分が埋もれる
- 図と本文で名前や向きが食い違う
