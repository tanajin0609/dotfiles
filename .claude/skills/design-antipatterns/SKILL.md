# design-antipatterns

嫌われるデザインは2種類ある。判定ではまずどちらかを決める。

- **量産された記号**: 誰も選ばずに出てきた定型。手抜きに見え、どのサービスか区別がつかない。→ 対処は「1箇所でいいので、この案件のために決めた要素を残す」
- **作り手の都合の押し付け**: 社内調整・法対応・見た目の新しさを、見る人の負担で解決している。→ 対処は「見る人の操作と可読性を優先する」。こちらの方が深刻度が高い

使ったら即NGではない。案件のブリーフが明示的に求めている場合はブリーフが優先する。問題は「選んでいないのに出てきた」こと。

| AP-07 | Corporate Memphis | 量産 | 頭が小さく手足の長い、紫や青の肌で顔のない人物イラスト | 実際のプロダクト画面・写真・案件固有のモチーフを使う |

## 使い方

**生成時（UIを作る前）**: デザイン案（配色・書体・レイアウト）を決めたら、コードを書く前に一覧の検出シグナルと照合する。該当したら、ブリーフが求めたものか、選ばずに出てきたものかを判定する。後者なら差し替え、何をなぜ変えたかを1行で添える。

**レビュー時**: 該当箇所ごとに以下の形式で出す。押し付け型を先、量産型を後に並べる。

```
[id] 名前（押し付け/量産） 対象箇所
  根拠: どのシグナルに該当したか（コード行 / スクショの箇所）
  改善案: 具体的な変更
```

uiux-review と同時に使う場合、AP-02 は同skillの `DARK-*`、AP-04/AP-05 はコントラスト項目と同じ事象になる。重複する場合は uiux-review 側の id で1件だけ出す。
