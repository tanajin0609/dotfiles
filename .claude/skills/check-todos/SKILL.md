# check-todos — 残タスク横断確認

## Step 1: todo.md を列挙する

```bash
find /home/igpf-2500009/projects -maxdepth 6 -path "*/docs/tasks/todo.md"
```

`self-work/<サブプロジェクト>/docs/tasks/todo.md`（5階層）・`ops-work/<カテゴリ>/<テナント>/docs/tasks/todo.md`
（6階層）を拾うため、直下プロジェクト（4階層）より深く探索する（2026-08-26変更）。

見つかったファイルのパス一覧を把握する。0件でもエラー扱いにせず、
「`docs/tasks/todo.md` を持つプロジェクトが見つかりませんでした」と伝えて終了する。

## Step 2: 各ファイルを読み、未完了項目を抽出する

見つかった todo.md をそれぞれ Read で読み込み、以下の基準で対象を絞る。

- 対象: `- [ ]` の未完了チェックボックス項目のみ。
- 対象外: `- [x]` の完了項目、「完了した実装」「運用メモ」等プレーンな箇条書きのセクション。
- 複数行にまたがる項目（次の `- [ ]` や見出しが出てくるまでの継続行）は1項目として扱う。
- 見出し（`##`/`###`）は、その項目がどの文脈の残課題かを示す情報として保持する。

## Step 3: プロジェクトごとに要約する

プロジェクト名は `todo.md` から2階層上（`docs/tasks/` の親）のディレクトリ名を使う。

各プロジェクトについて、未完了項目を1〜3行程度に要約する。項目数が多い場合は
主要なテーマ単位（例:「PoCレビュー会の未決事項」「Phase1の技術的負債」）でまとめ、
本文の逐語コピーはしない。

未完了項目が0件（ファイルはあるが空、または全項目が完了済み）のプロジェクトは
「残タスクなし」と一言で示す。

## Step 4: 出力する

ターミナル（会話内テキスト）にのみ表示する。ファイルの新規作成・書き込みは一切行わない。

出力形式の例:

```
## 残タスク確認（対象 {N} プロジェクト）

### {プロジェクト名}
- {要約1}
- {要約2}

### {プロジェクト名}
残タスクなし
```

---

## 注意事項

- read-only。todo.md やその他のファイルへの書き込みは行わない。
- 完了済み項目・運用メモ節は要約に含めない。
- 複数プロジェクト間の優先順位付けや「何から着手すべきか」の提案はしない。
  事実（何が残っているか）の列挙に徹し、判断はユーザーに委ねる。
