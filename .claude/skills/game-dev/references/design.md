# 企画・ゲームデザイン

## コンセプトを1文にする

型: 「〈プレイヤー〉が〈操作〉をして〈気持ちよさ〉を得るゲーム」。

- 悪い例: 「ローグライク要素のある2Dアクション」（ジャンル名の列挙で、何が気持ちいいか分からない）
- 良い例: 「弾を撃つ反動でしか移動できず、撃つほど危険な方向へ飛ばされるアクション」

1文に書けない要素は、コアではない。後回しか削除の候補にする。

## コアループ

プレイヤーが繰り返す行動の輪を3層で書く。内側が面白くなければ外側を足しても直らない。

```
秒単位   : 操作 → 反応 → 結果          （例: 狙う → 撃つ → 当たる/外す）
分単位   : 挑戦 → 報酬 → 強化の選択    （例: 部屋を攻略 → 報酬 → 装備を選ぶ）
時間単位 : 進行 → 解放 → 新しい挑戦    （例: ボス撃破 → 新エリア）
```

プロトタイプで検証するのは秒単位の層だけでよい。

## プロトタイプで検証する仮説

仮説は「〜なら〜と感じるはず」の形で書き、判定方法を先に決める。

| 仮説の例 | 判定方法 |
|---|---|
| 反動移動は30秒で操作を理解できる | 説明なしで触ってもらい、30秒以内に意図した方向へ動けるか |
| 失敗しても即リトライしたくなる | 死亡後に自分から再開するか（促されずに） |
| 3分遊んでも単調にならない | 3分後に手が止まるか、続けるか |

判定が「微妙」だったら、数値調整で粘るのは2〜3回まで。それで変わらなければ仮説そのものを変える。

## スコープの決め方

- **作らないものリスト**を先に書く（例: オンライン対戦、セーブスロット複数、実績、多言語）。
- 量で見積もる: ステージ数・敵の種類・武器の種類を数字で出す。「敵10種」は、挙動の違う敵を10回設計・実装・調整するという意味。
- 迷ったら「種類を増やす」より「少ない種類の組み合わせで変化を出す」を選ぶ（例: 敵3種 × 地形3種で9通りの状況）。
- 初めての完成を目指すなら、遊べる時間は5〜15分の規模から始める。

## 難易度とレベルデザイン

- **1つずつ教える**: 新しい要素は、安全な状況で単独で出す → 既知の要素と組み合わせる → 時間制限や危険を加える、の3段階で出す。
- **緩急**: 難しい場面の後には易しい場面を置く。右肩上がりの一直線にしない。
- **失敗のコスト**: やり直し地点までの距離が長いほど、難しさは不満に変わる。難しくするならリトライを速くする。
- **原因が見える失敗**: やられた理由がプレイヤーに分かること。画面外からの攻撃・予兆のない即死は避ける。
- チュートリアルは文章より状況で教える（例: 最初の穴はジャンプしないと越えられないが、落ちても死なない）。

## 数値設計

- 基準値を1つ決め、他はその倍率で表す（例: プレイヤーの基本攻撃=10。敵の体力は「何発で倒れるか」から逆算）。
- 成長は「何分で次の強化が手に入るか」から逆算する。計算式から決めない。
- 乱数は体感と一致しないことが多い。連続で外れ続けない仕組み（一定回数で確定など）を検討する。
- 数値は表（CSVやJSON）にまとめ、Claudeには「表のこの列を±20%」のように依頼できる形にする。

## 報酬と継続の動機

- 行動の直後に小さい反応（音・エフェクト・数字）、区切りで大きい報酬（解放・新要素）を返す。
- プレイヤーに選ばせる報酬（3択など）は、同じ内容でも納得感が高い。
- 課金・ログインボーナスなどで不安や損失回避を煽る設計は、依頼されても先にリスク（規約・年齢層・評判）を伝える。
