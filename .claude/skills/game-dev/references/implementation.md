# 実装・技術

## エンジン選定

Claudeと作る場合の最重要観点は「Claudeがテキストだけで編集・実行・確認できる範囲の広さ」。エディタ上のマウス操作が必要な作業は人に戻るため、往復が遅くなる。

| 候補 | 向く用途 | Claudeが直接できること | 人の操作が要ること |
|---|---|---|---|
| Web（HTML Canvas / JSライブラリ） | 2D、小規模、すぐ見せたい試作 | コード全部、ブラウザ自動操作での起動確認・スクリーンショット | ほぼ無し（プレイ判定のみ） |
| Godot | 2D全般、小〜中規模3D | スクリプト、テキスト形式のシーン/リソース編集、コマンドラインからの実行 | エディタでの細かい配置、アニメーション調整 |
| Unity | モバイル、中規模3D、資料の多さ重視 | スクリプト、コマンドラインからのテスト/ビルド | シーン・プレハブの編集（ファイルは内部ID参照が多く、手書き編集は壊しやすい） |
| Unreal Engine | 高品質3D | C++コード | ビジュアルスクリプトやレベル編集の大半（バイナリ資産） |
| ノーコード系（ノベル・RPG制作ツール） | 物語中心、定型ジャンル | シナリオ・データの文章作成 | ツール上の組み立て |

選び方の順番: 公開先（ブラウザ/PC/スマホ/家庭用機）→ 2Dか3Dか → 人がエディタ操作に使える時間。迷ったら、試作はWebで作り、面白さが確認できてから本番エンジンを選び直してよい。

各エンジンのライセンス料・対応プラットフォーム・コマンドライン機能は変わるため、採用前に公式情報で確認する。

## 基本構造

```
入力 → 更新（ロジック） → 描画
        ↑ 固定の時間刻みで回す
```

- **更新と描画を分ける**。ロジックは固定の時間刻み（例: 1/60秒）で進め、描画は可能な速さで行う。フレームレートで速度が変わる不具合（速いPCでキャラが速い）を防ぐ。エンジン使用時は物理用の固定更新とフレーム更新の使い分けに従う。
- **移動量には経過時間を掛ける**（`位置 += 速度 × dt`）。固定刻みでない更新で必須。
- **ロジックを描画・エンジンAPIから切り離す**。ダメージ計算・当たり判定・進行条件を純粋な関数にしておくと、画面なしで自動テストできる（→ `test-release.md`）。

## 状態管理

- 画面遷移（タイトル/プレイ中/ポーズ/リザルト）と、キャラクターの状態（待機/移動/攻撃/被弾）は**状態機械**で書く。真偽値フラグの組み合わせ（`isJumping && !isAttacking && ...`）で書くと、ありえない組み合わせがバグになる。
- 「どの状態からどの状態へ移れるか」を表か図で先に出す。
- ポーズは早い段階で入れる。後付けすると、止め忘れるタイマーや音が出る。

## データ駆動

- 敵・武器・ステージの定義はデータ（JSON/CSV/エンジンのリソース）に置き、コードは定義を読んで動く形にする。種類を足すときにコードを触らずに済む。
- ただし種類が3つ以下のうちは直書きでよい。早すぎる汎用化は試作を遅くする。
- 部品の組み合わせで物を作る（移動する/撃つ/体力を持つ、を別部品にする）。深い継承（敵 → 飛ぶ敵 → 撃つ飛ぶ敵）は組み合わせが増えると破綻する。

## 入力

- キー/ボタンを直接見ず、「ジャンプ」「決定」などの**行動名**に割り当ててから使う。キーボード・ゲームパッド・タッチの切り替えとキー設定変更が後から可能になる。
- 押した瞬間・押している間・離した瞬間を区別する。
- 手触りに効く入力処理（先行入力、足場を離れた直後のジャンプ猶予）は `art-sound-ui.md` を参照。

## 乱数・セーブ

- 乱数は種（seed）を指定できる生成器を1つ通して使う。同じ種で同じ展開を再現でき、バグ報告と自動テストが成立する。
- セーブデータには最初から**バージョン番号**を入れる。公開後に形式を変えるとき、古いデータを読み替える足場になる。
- セーブするのは「再構築に必要な最小の状態」。画面上のオブジェクトを丸ごと保存しない。

## 性能

計測してから直す。推測で最適化しない。よくある原因は次の順。

| 症状 | よくある原因 | 対処 |
|---|---|---|
| 周期的にカクつく | 弾・エフェクトの生成と破棄によるメモリ確保/回収 | 使い回す（オブジェクトプール） |
| 物が増えると重い | 全対全の当たり判定 | 空間を区切って近いものだけ判定、判定レイヤーで対象を絞る |
| 描画が重い | 描画命令の回数、重なった半透明、大きすぎるテクスチャ | 画像をまとめる、画面外を描かない、解像度を下げる |
| 読み込みが長い | 起動時に全素材を読む | 場面ごとに読む、非同期で読む |

目標フレームレートと最低動作環境を基本設計で決め、その環境で測る。

## 開発用の仕掛け

早めに入れると、人の確認とClaudeの確認が両方速くなる。

- 任意のステージ・状態から開始する手段（起動引数やデバッグメニュー）
- 無敵、速度変更、当たり判定の可視化
- 画面上のFPS・オブジェクト数表示
- 公開ビルドでは無効になる切り替え（消し忘れが事故になる）
