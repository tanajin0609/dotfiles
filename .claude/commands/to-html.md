# /to-html — Markdown → HTML（designer 一本化）

冒頭で `~/.claude/skills/doc-rules/SKILL.md` を Read し、ドキュメント横断ルールを確認してから実行する。

現セッションの Claude が md を直接 Read → HTML を Write する。Python 決定的レンダラ（旧 auto モード）は廃止。図表・カード・Hero を含むインフォグラフィック相当の HTML を毎回作る。

## 入力仕様

- `/to-html <md_path>`
- 旧モード名は **全て designer に正規化**（破壊的変更を避けるため受理だけする）
  - `simple` / `rich` / `auto` / `fancy` / `designer` → 全部 designer 動作
- `<md_path>` 省略時はカレントディレクトリで以下の優先度で自動検出
  1. `plan.md`
  2. `spec.md`
  3. `report*.md`（更新日時最新）
  4. `research.md`
  5. どれも見つからない場合は AskUserQuestion でパスを聞く

## 設計方針

- **単一モード**: designer のみ。Python レンダラへの分岐は無い。
- **セッション内処理**: 別プロセス / 別 API 課金は発生しない。本セッションの Claude が直接 HTML を書く。
- **md が canonical source**: HTML だけに新規の伝達内容を入れることは禁止。情報追加が必要なら md を先に更新する。
- **トレードオフ**: 会話コンテキストを重く消費する（md と HTML 双方を扱うため）。バッチ / CI 用途には向かない。

## 共通ルール

- 出力: 入力 md と同ディレクトリの `<basename>.html`
- 上書き保護マーカー
  - 既存 HTML がマーカー無し（手書き想定） → 上書きしない
  - 既存 HTML が以下のいずれかのマーカー → 上書き可
    - `<!-- generated-by: to-html-designer -->`（新・現行）
    - `<!-- generated-by: to-html-auto -->`（旧、互換）
    - `<!-- generated-by: md2html -->`（旧 simple、互換）
    - `<!-- generated-by: md2html-rich -->`（旧 rich、互換）
    - `<!-- generated-by: md2html-fancy -->`（旧 fancy、互換）
- 個人情報マスクは designer 出力前に自動適用される（UUID / FIT コード / 会員番号）

## ワークフロー

### Step 1: 引数確定
- `<md_path>` を解決し `ls -la` で実在確認（**md ファイルが無ければここで停止**。HTML だけ作るのは禁止。md が canonical source）
- 拡張子が `.md` であること、ファイルが UTF-8 で読めること
- 旧モード引数が渡されてもエラーにせず無視して designer 動作する

### Step 2: designer 生成
1. md を `Read` ツールで取り込む
2. **md の充足チェック**（必須）— HTML に出したい以下の「伝達内容」が md 側に存在するかを確認し、無ければ **md 側を先に Edit/Write で追記してから** HTML 生成に進む。HTML だけに新規の伝達内容を入れることは禁止（md ⇔ html の同期ルール厳守）:
   - 文書 H1 直下の Lede 文章（短い導入段落） — Hero として描画する内容
   - サマリ章（指標・キー数値・件数等） — メトリクスカードとして描画する内容
   - 各章の本文・表・コードブロック・コールアウト — そのまま HTML 化される内容
   - 装飾だけ（gradient 背景・色・カード枠線・SVG イラスト）は md に書かなくてよい（同期ルール例外節）
3. **現セッションの Claude が直接** 以下を一気に組み立てて HTML を書く:
   - md 本文を HTML 構造へ変換（見出し / 段落 / リスト / 表 / コードブロック / コールアウト / カード）
   - 目次（TOC）— md の `## ` 以下を拾って組む
   - Hero 領域（md の H1 + Lede 文章をそのままビジュアル化）
   - 重要セクションをカード化、キーメトリクスを大きな数字で強調（数値・項目は md のサマリ章から拾う）
   - 数値テーブルがあれば Chart.js などで図化（bar / line / pie / donut を内容に応じて選ぶ）
   - 数値以外でも構造化された情報（フロー・関係性・分類）は SVG で図化を検討
   - コールアウト記法（`> [!NOTE]` / `[!WARN]` / `[!OK]` / `[!RISK]`）を視覚化
   - カラーパレットを文書の文脈に合わせて調整
   - 余白・タイポグラフィの微調整
   - 共通 CSS（`work/self-task/improve-skills/html/assets/base.css` + `components.css` + `rich.css`）を**インライン展開**して埋め込む
4. 先頭にマーカー `<!-- generated-by: to-html-designer -->` を必ず付与
5. `Write` ツールで `${MD_PATH%.md}.html` に保存（マーカーチェックを満たす場合のみ）

> **重要 1**: designer は外部 `claude -p` プロセスを起動しない。本セッションの Claude が直接 HTML を書く。
> **重要 2**: **md が canonical source**。HTML に新規の伝達内容を入れたい場合は、必ず md を先に更新してから HTML を生成する。逆順（HTML 先・md 追従）はルール違反。
> **重要 3**: 「図表が無くて寂しい HTML」は失格。テーブル・リスト・フローチャート対象の情報がある場合は Chart.js / SVG / カードレイアウトを必ず使う。装飾密度は「インフォグラフィック」を基準にする。

### Step 3: 結果案内
- 生成 HTML の絶対パスをユーザに伝える
- 自動でブラウザを開かない（必要なら `wslview <path>` を案内）

## 既存スキルとの関係

- `/patch-report`: 実装完了レポート生成。HTML 化したい場合は完成後に `/to-html report-*.md` を続けて呼ぶ

## .md ⇔ .html 同期ルール

**役割:** `.md` は **AI 用**（Claude が canonical source として読む情報本体）、`.html` は **人間用**（ブラウザで読むためのレビュー view）。両者は同じ情報を異なる読み手向けに表現したもの。

**原則:** 同名の `.md` と `.html` が同じディレクトリに存在する場合、両者は**常に完全一致**させる（内容・章立て・例示・テーブル・コードブロック・Lede 文章・サマリ数値すべて）。変更が入った場合は**必ず両方更新**する。

- いずれか一方を編集したら、**同じコミット内でもう一方も同等の変更を適用**する。片方だけの更新は不可
- 既に乖離している状態を見つけたら、ユーザーに「どちらを正とするか」を確認してから同期する
- HTML が `to-html` で生成されている場合でも、`.html` を手動で直接編集したなら `.md` を手動で追従させる（再生成で済むなら再生成する）

### md に書かなくてよいもの（HTML 固有の純装飾のみ）

- gradient 背景・カラーパレット・カード枠線・シャドウ
- SVG イラスト・アイコン・フォントサイズ・余白・行間
- レスポンシブブレークポイント・ダーク/ライト切替

### md にも必ず書くもの（情報・データ・構造）

- 文書冒頭の Lede 文章（H1 直下の導入段落）
- サマリ章のメトリクス数値・件数・指標
- 各章本文・表のデータ・コードブロック・コールアウトの文面
- 章構造（h2 / h3 の見出し）と章の並び

> **誤解しがちな点**: HTML に「メトリクスカード 4 枚」を表示するなら、md にも対応する「サマリ表（4 行）」が必要。逆も同様。視覚化の形（カード／表／リスト）は HTML 側で選んでよいが、**運ぶ情報量は完全一致**させる。

## トラブルシュート

- 既存 HTML が更新されない: マーカー無しの手書き HTML → 手動退避してから再実行
- チャートが描画されない: ブラウザコンソール確認。Chart.js CDN（jsdelivr）不達の可能性
- 図表が少ないと感じる: md 側にテーブル・サマリ章・数値が無いのが原因。md を先に充実させる
