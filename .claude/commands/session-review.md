# /session-review — 月次セッション振り返り

手順だけを持つ。何を拾うかは観点ファイルが決める。仕様は `~/projects/self-work/fix-skill/docs/specs/session-review.md`。

## パス

| 名前 | パス |
|---|---|
| ダイジェスト生成 | `~/projects/self-work/fix-skill/src/build_session_digest.py` |
| 既定の観点 | `~/projects/self-work/fix-skill/src/session_review_viewpoints.default.md` |
| 観点 | `~/.claude/local/session-review/viewpoints.md` |
| 出力 | `~/.claude/local/session-review/journal/<YYYY-MM>.md` |

## 手順

1. 対象月を決める。`$ARGUMENTS` が `YYYY-MM` ならそれ、空なら前月。
2. 観点ファイルが無ければ、既定の観点を `mkdir -p` の上でコピーする。観点ファイルを読む。
3. ダイジェストをパート分割で書き出す（作業用ディレクトリは `$CLAUDE_JOB_DIR/tmp`、無ければ `/tmp`）:
   `python3 <ダイジェスト生成> <YYYY-MM> --out-dir <作業用ディレクトリ>/digest-<YYYY-MM>`
   標準出力にパートのパスが並ぶ。標準エラーに警告が出たら、内容をそのまま報告して止める。
4. パートが1つなら自分で全行読む。2つ以上なら、パートごとに `general-purpose` サブエージェントを1つのメッセージで並列に起動する（1か月分は1MBを超え、1コンテキストで読み切れないため）。各サブエージェントには、パートのパス・観点ファイルのパス・下の「記述規則」をそのまま渡し、観点ごとの該当項目（日付・作業ディレクトリ・根拠）だけを返させる。ファイルは書かせない。
5. 観点ごとに該当する出来事を統合する。各項目に日付・作業ディレクトリ・根拠の行（U/A/S/B の該当文の要約）を付ける。サブエージェントの結果は、根拠の無い項目を落としてから使う。
6. 出力ファイルが既にあれば、上書きするかを AskUserQuestion で確認する。生ログは約30日で消えるため、過去月の再生成は内容が減ることがある旨を設問に書く。
7. 出力ファイルに書き、パスと観点ごとの件数を報告する。

## 記述規則（事実のみ）

- ダイジェストに根拠がある事実だけを書く。やっていないことは書かない。
- 言及がないことを「やっていない」と断定しない。根拠が無ければ「記録なし」と書く。
- 評価・称賛の形容（「適切に」「丁寧に」等）を付けない。

## 出力の形

```markdown
# 振り返り <YYYY-MM>

対象: 生ログ由来 N セッション / events 由来 M セッション（ダイジェスト先頭の件数）

## <観点1の見出し>
- <MM-DD> `<作業ディレクトリ>`: <出来事>（根拠: <行の要約>）

## <観点2の見出し>
- 記録なし
```
