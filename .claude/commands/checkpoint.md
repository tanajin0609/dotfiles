# /checkpoint — 中間状態保存コマンド

引数 `$ARGUMENTS`: 任意のメモ（例: 「ピッチデック生成の途中」）。空でも可。

## 動作

現在の対話文脈から **5項目** を抽出し、Markdown ファイルとして保存する。
**自動 hook ではなく明示コマンド**（誤発火を避けるため）。

## 保存先と命名規則

1. **対象プロジェクトが特定できる場合**: `<currentProject>/checkpoints/YYYYMMDD-HHMM.md`
   - 例: `~/projects/<project-name>/checkpoints/20260510-1430.md`
2. **特定できない場合**: `./checkpoints/YYYYMMDD-HHMM.md`（作業ディレクトリ直下）
3. ディレクトリが無ければ作成する（`mkdir -p`）
4. 同タイムスタンプで衝突したら `-2`/`-3` を付ける

## チェックポイント・テンプレート（5項目）

```markdown
# Checkpoint — YYYY-MM-DD HH:MM

**メモ**: $ARGUMENTS（あれば）

## 1. 現在のゴール
（このセッションで何を達成しようとしているか。1〜3行）

## 2. 直近の決定事項
（採用したアプローチ・却下した選択肢を箇条書き）

## 3. 残タスク
- [ ] （未着手・進行中の作業）
- [ ] ...

## 4. 次の一手
（このチェックポイントから再開する際、最初にやること）

## 5. 保留中の質問
（ユーザー判断待ちの項目。なければ「なし」）
```

## 実行手順

1. 現在時刻から `YYYYMMDD-HHMM` を生成（`date +%Y%m%d-%H%M`）
2. 保存先パスを決定（上記ルール）
3. `mkdir -p` で `checkpoints/` ディレクトリを確保
4. 5項目テンプレートを埋めて `Write`
5. 保存先パスを1行でユーザーに返す

## 禁止事項

- 既存 checkpoint ファイルを上書きすること（必ず新規ファイル）
- ユーザーに項目内容を確認しないまま、無いものを「なし」で埋めること
  - 不明な項目は `AskUserQuestion` で1回だけ確認してよい
- `git add`/`commit` を勝手に実行すること（チェックポイントは作業ファイル扱い）
