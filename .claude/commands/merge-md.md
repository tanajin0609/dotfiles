# /merge-md — Markdown マージ専用コマンド

引数 `$ARGUMENTS`: マージ元と先のファイル指定、またはマージ意図の自然言語記述。

## 基本ルール（厳守）

1. **In-place 原則**: マージ先ファイルを **上書き編集** する（`Edit`/`Write` でマージ先パスを指定）
   - 新規ファイル作成は禁止。必要と判断した場合は **事前に `AskUserQuestion`** で確認
2. **重複排除**: 同一行・同一見出しは **マージ先の既存内容を優先** し、ソース側の重複は捨てる
3. **カラム順保持**: 表形式の場合、マージ先の列順を維持。ソース側の列順が違っても揃える
4. **見出し階層維持**: マージ先の見出し階層（`#`/`##`/`###`）に合わせて挿入する
5. **曖昧時の逃げ道**: 以下の判断で迷ったら **必ず `AskUserQuestion`** を投げる
   - 重複行の判定基準（完全一致 vs 一部一致）
   - 挿入位置（先頭・末尾・特定見出し直下）
   - カラム名の表記揺れ（同義カラムをまとめるか別カラムにするか）

## 実行手順

1. マージ元・マージ先を特定する（曖昧なら `AskUserQuestion`）
2. 両ファイルを `Read` で読み込む
3. 構造を把握する（見出し / 表 / 箇条書き）
4. ルール 1〜4 に従ってマージ後のテキストを構築する
5. **マージ先のパス** に `Edit` または `Write` で書き戻す
6. 結果サマリは1〜3行で返す（追加行数・除外重複数・要確認事項のみ）

## 使用例

```
/merge-md A.md と B.md をマージ。マージ先は A.md
/merge-md 振込明細を ledger.md に追記（重複は除外）
```

## 禁止事項

- 挨拶・前置き・テンプレ全文の挿入（`Response Style` ルール準拠）
- 元ファイルを残したまま新規 `merged.md` を作る（事前確認なしでは禁止）
- マージ先のフォーマット（表 vs 箇条書き）を勝手に変換する
