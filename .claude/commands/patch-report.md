# /patch-report — 実装完了レポート生成

冒頭で `/home/igpf-2500009/.claude/local/doc-rules/RULES.md` が存在すれば Read し、ドキュメント横断ルールを確認してから実行する（存在しない環境では無視して続行する）。

このコマンドを実行すると、今回の実装内容をもとに `report/` フォルダに `.md` レポートを生成します。

## ワークフロー

### Step 1: 実装内容の把握

以下の順で情報を収集する:

1. カレントディレクトリの `plan.md` を Read で読んで実装スコープを把握する（なければ会話の文脈を使用）
2. plan.md に記載されている変更ファイルを Read で読み、実際の差分を確認する
3. カレントディレクトリの `issue.md` を Read し、ステータスが `進行中` / `調査中`（未解決）の Issue を抽出する（存在しない場合はスキップ）

### Step 2: レポート生成

以下のテンプレートで `report/patch-report-YYYYMMDD.md` を生成する。

- YYYYMMDD は今日の日付
- 同日2件目以降は `patch-report-YYYYMMDD-2.md`、`patch-report-YYYYMMDD-3.md` とする
- `report/` ディレクトリが存在しない場合は先に作成する
- タイトルは plan.md の内容または会話の文脈から自動生成する

### Step 3: 生成後の案内

生成したファイルパスをユーザーに伝える。

## レポートテンプレート

```markdown
# {タイトル}

**更新日:** YYYY年M月D日

---

## 概要

（何を・なぜ変更したか、3文以内）

## 実装内容

| ファイル | 変更内容 |
|---------|---------|
| `path/to/file` | 変更の要点 |

## 変更仕様の差分

- **変更前:** ...
- **変更後:** ...

## 次のステップ

- ...

## 課題・リスク

（issue.md の未解決 Issue（進行中/調査中）から自動抽出。なければセクションごと省略）
```

## 注意事項

- 概要は3文以内（CLAUDE.md 規則）
- 技術詳細よりビジネス上の成果を優先して記述
- 「課題・リスク」は issue.md の未解決 Issue（進行中/調査中）から自動抽出する。手動で推測を追記しない
- 課題・リスクがなければセクションごと省略する
- plan.md が見つからない場合は、会話の直前の実装内容から生成する
