# /game-proto — 試作を1周回す

引数: `$ARGUMENTS` = コンセプト（新規）または「試作のディレクトリ + 次に試す仮説」（継続）。

最初に game-dev skill（`SKILL.md` と、該当する `references/`）を読む。以下はその手順を固定したもの。

## 0. 置き場所と状態の確認

- 置き場所: 引数で指定されていればそこ。無ければカレントディレクトリ直下の `<英小文字の短い名前>/`。カレントが共有設定のリポジトリ（`.claude/skills` を含む）の場合や決められない場合は AskUserQuestion で聞く。
- 継続の場合: `playlog.md` を読む。**「人の判定」が空の行があり、今回の変更がルールや調整値に触れるなら、実装せずに止まり**、判定待ちの行と「触って見てほしい点」を再掲する。

## 1. 企画（新規のみ）

1. コンセプトを「〈誰が〉〈何をして〉〈何が気持ちいいか〉」の1文にする。書けなければ AskUserQuestion。
2. 秒単位のコアループを1行で書く。
3. 今回検証する仮説を1つだけ決め、「〜なら〜と感じるはず」と判定方法を書く。
4. コンセプトの言葉を、数えられる主張に1つ以上直す（`references/design.md`）。
5. 作らないものを3つ以上挙げる。

## 2. 実装

1. 新規なら、skill の `assets/prototype/` から `game.js`・`index.html`・`measure.js`・`playlog.md` をコピーする。
2. `game.js` の中身をこのゲームのルールに書き換える。契約（ファイル冒頭のコメント）は守る: 描画・DOM・時計に触れない、ルールと遊び方（bots）の数値は `CONFIG` だけ、`bots` に `idle`（何もしない）・`random`（でたらめ）・最も素朴な正攻法を置く。押した瞬間に反応する操作は `input.pressed`、押している間の操作は `input.active` を使う。
3. `index.html` は、冒頭の印より上の `TEXT`・`drawGame`・`deathText` と、`<title>`・`<h1>`・操作説明の `<p class="hint">` だけを書き換える。入力やループの枠は触らない（枠で足りない操作が要るなら、枠を直す前に報告する）。素材は図形のまま。描画専用の数値は `drawGame` に書いてよい。
4. 継続なら、仮説に対応する変更を1つだけ入れる。

## 3. 機械で確かめる

1. `node measure.js game.js` を実行する。
2. **先に遊び方（bots）を疑う**。正攻法が `idle` や `random` より長く生きていなければ、ゲームではなく正攻法の実装ミスの可能性が高い。1戦を追跡して直す。これは下の「3回」に数えない。
3. 赤信号が出たら、人に渡す前に直す。`CONFIG` の数値を1回に1項目だけ、±20〜50%の幅で変え、同じ計測で消えたかを確かめる。消えなければ**元に戻してから**別の項目を試す（重ねない）。3回試しても消えなければ、数値ではなくルールの構造が原因と見て、そのまま出して報告に書く。
4. 手順1-4の「数えられる主張」を計測する。`measure.js` が出さない数字は使い捨てスクリプトで測る。成立していなければ数値では粘らず、直さずに `playlog.md` と「触って見てほしい点」へ書く（狙った展開が出ていないことを、人の判定で確かめる）。
5. ルールに触れない変更（見た目・音）だけの回は、変更前に `--save`、変更後に `--compare` で完全一致を確かめる。新規作成の回は対象外。
6. ブラウザで起動し、実際のキー入力またはポインタ入力で「開始 → 操作が効く → 終了 → やり直し」を通す。コンソールエラー0件、スマホ幅で横スクロール無しを確かめる。
   - `index.html` は公開ページ用の断片（doctype・body なし）。ローカルでは `<!doctype html><html><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1"></head><body style="margin:0">…</body></html>` で包んだ `local.html` を同じ場所に作って開く。
   - 状態は `window.__game.state`（mode・player など）で読める。

## 4. 人に渡す

1. 遊べる形で渡す。公開ページなら `index.html` に `game.js` を添える。ローカルなら手順3-6の `local.html` を開いてもらう。
2. `playlog.md` の「コンセプト:」を埋め（新規のみ）、表に1行足す: 仮説・入れた変更・機械の計測（赤信号の有無と主な数字）。「人の判定」は空のまま。
3. game-dev skill の報告形式で報告する（変更／確認済み／触って見てほしい点／調整つまみ／判定待ち）。

## 5. 判定が返ってきたら

`playlog.md` の該当行に「人の判定」（どこで・何回・何が起きたか）と「次の一手」を書く。次の一手は `references/design.md` の「原因の当たりをつける」表から1つ選ぶ。「もう1回やりたい」が出たら、基本設計へ進むかを AskUserQuestion で聞く。
