# 提案書: 未完了マイルストーンの申し送り（defer）を形式化する

> 対象読者: document-rules.md のメンテナ（自分）
> スコープ: `/todo-execute`が「一部失敗」「スキップ」としたマイルストーンの申し送り方法を定型化し、
>   `/todo-propose`が次サイクルで自動的に拾えるようにする
> 元セッション: 2026-09-02
> 結論: **決定・本セッション内で反映**

## 1. 経緯

Qiita記事（AIタスク管理ワークフローの事例）に、無人実行で未完了タスクを「理由・次の一手・
推奨モデル」付きで`defer`として申し送る仕組みが紹介されていた。現状の`/todo-execute`は
Step3（サブエージェント報告フォーマット）に「未解決点・次アクション」という自由記述欄は
あるが、構造化されておらず、`plan-YYYY-MM-DD.md`に書かれた申し送りを次サイクルの
`/todo-propose`が読み取る導線も無い。結果として、一部失敗・スキップしたマイルストーンが
次回何のフォローもなく埋もれる可能性がある。

## 2. 【決定】defer情報を構造化し、記録先を二重化する

**深刻度: 中 / 確度: 高**

- `/todo-execute`が完了できなかったマイルストーンについて、以下4項目を構造化して記録する。
  - **状態**: `pending`（未着手のまま）/ `blocked`（依存待ち）/ `partial`（部分完了）
  - **理由**: なぜ完了しなかったか
  - **次の一手**: 次に何をすれば前進するか（具体的な調査対象・コマンド）
  - **推奨モデル/エフォート**: 変更する場合のみ記載（当初提案からの見直し）
- 記録先は**二重**とする（今回の合意事項）。
  - `today-todo/plan-YYYY-MM-DD.md`の該当マイルストーン見出し下に、上記4項目を詳細に記録する
    （実行計画ファイルであり、当日以降も参照される前提のため）。
  - 対象サブプロジェクトの`docs/tasks/todo.md`（正の情報源）には、defer理由の要約1行と
    `plan-YYYY-MM-DD.md`への参照リンクを追記する（「正の情報源→today-todoへ反映」という
    既存の一貫性原則に合わせるため。二重管理にはなるが、要約行と詳細を役割分担させることで
    許容する）。
- 次サイクルでの拾い上げは、`/todo-propose`バッチモードの一次判定（0-3）に新しい区分を追加し、
  **自動検出**させる。`todo.md`のdefer行を検出したら、参照先`plan-YYYY-MM-DD.md`の詳細を読み、
  次の一手・推奨モデルを引き継いだ形でマイルストーン再提案に反映する（ゼロから調査し直さない）。

## 3. 反映範囲

- `document-rules.md`: 「defer情報の形式化」節を新設し、記録先2箇所の役割分担と
  拾い上げ導線を明記する。
- `~/.claude/commands/todo-execute.md`:
  - Step3（報告フォーマット）の「未解決点・次アクション」を、上記4項目の構造化フォーマットに置換。
  - Step5に、一部失敗・スキップのマイルストーンについて `plan-*.md`への詳細記録と
    `docs/tasks/todo.md`への要約行追記を明示的な作業として追加。
- `~/.claude/commands/todo-propose.md`:
  - 0-3（一次判定表）に「defer項目（前回の申し送り）」区分を追加。
  - 3-1a（マイルストーン提案の書き方）に、defer項目を引き継ぐ場合は次の一手・推奨モデルを
    転記し、変更点があれば明記する旨を追加。
