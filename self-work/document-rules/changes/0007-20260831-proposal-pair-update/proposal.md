# 提案書: `today-todo/proposal-YYYY-MM-DD.md`も正の情報源とのペア更新対象に加える

> 対象読者: document-rules.md のメンテナ（自分）
> スコープ: `[[0005-20260824-dual-update-source-and-today-todo]]`で明文化した更新ペア原則の対象を
>   `today-todo/todo-YYYY-MM-DD.md`から`today-todo/proposal-YYYY-MM-DD.md`にも拡張する
> 元セッション: 2026-08-31
> 結論: **決定・本セッション内で反映済み**

## 1. 経緯

2026-08-31、`today-todo/proposal-2026-08-31.md`のM1節（review-hub 4提案の承認待ち）について
ユーザーから「もう確認事項ない？」と聞かれ、proposal-2026-08-31.md記載どおり「未承認・要確認」と
回答した。しかし実際には、対象4件（F6起動方式・F8通知方式・永続化方式の決定、およびF6・F7の実装）は
`self-work/review-hub/docs/tasks/todo.md`（正の情報源）上ではすでに決定・実装済みだった。

`today-todo/todo-2026-08-31.md`は正の情報源とのペア更新原則（0005）に従い都度反映されていたが、
`today-todo/proposal-YYYY-MM-DD.md`（まとめ版）は「報告の写しであって、新しい判断を足さない」という
性質上、事後更新の対象として明記されておらず、当日時点のスナップショットのまま放置されていた。
その結果、まとめ版だけを見ると完了済みの作業が未完了に見える状態になった。

## 2. 【決定】`proposal-YYYY-MM-DD.md`の該当節も更新ペアの対象に含める

**深刻度: 中 / 確度: 高**

- `today-todo/proposal-YYYY-MM-DD.md`は引き続き「バッチモード実行完了時点の報告の写し」であり、
  新しい判断を事後的に書き足すものではない（0002での位置づけは変えない）。
- ただし、同ファイルが参照する対象（新規起票・既に提案済み・進行中・人間の決定待ち等）について
  正の情報源側で決定・完了が確定した場合は、**該当節（判定集計表の該当行、新規起票一覧の該当項目、
  「今日のゴールとマイルストーン」の該当マイルストーン）を「完了」に更新する**。
- 更新は差分反映（該当箇所の書き換え・完了マーク追加）とし、全文re-generateはしない
  （`todo-YYYY-MM-DD.md`と同じ扱い）。

## 3. 反映範囲

- `document-rules.md`:
  - 「`today-todo/proposal-YYYY-MM-DD.md`（まとめ版）について」節に、事後更新の例外（本決定）を追記。
  - 「How to apply」節に「正の情報源の変化は`todo-YYYY-MM-DD.md`だけでなく、当日分の
    `proposal-YYYY-MM-DD.md`が存在すればその該当節にも反映する」を追記。
- `today-todo/proposal-2026-08-31.md`: M1節（review-hub 4提案）を完了記述に更新（本提案と同一セッションで対応）。

## 4. 追加の教訓（同一セッション内で発覚）

M1節・3節（Checkerの発見事項1点目）を完了記述に更新した直後、ユーザーから「4節（留保・未確定事項）
に残すと結局終わってるのかわからない」との指摘を受けた。確認すると、4節・5節（次アクション）にも
「3節の2点はユーザー判断待ち」という同じトピックへの言及が残っており、3節側だけ直して4・5節を
見落としていたため矛盾が生じていた。`today-todo/proposal-YYYY-MM-DD.md`は複数節（判定集計・
発見事項・留保事項・次アクション・マイルストーン）が同じトピックに重複して言及する構成のため、
**該当節を1箇所だけ直すのではなく、対象キーワードでファイル全文を検索してから全ての言及箇所を直す**
運用に修正した（document-rules.mdの該当節に追記済み）。
