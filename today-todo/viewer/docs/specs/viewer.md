# viewer 仕様

`today-todo/todo-YYYY-MM-DD.md` をカンバン表示するローカルビューア（`server.js` がAPIと `index.html` を配信）。
基本仕様（列・カードの解釈、`data/` の保存形式、ポート）は `README.md` を参照。本書は受け入れ条件（AC）を置く。
ACのIDは導入したchangeの項目ID（`docs/changes/v0.10.0-feat-uiux-brushup-20260924/proposal.md`）に揃える。

対象環境はデスクトップ幅（1024px以上）。375px等のモバイル幅での崩れは対象外（2026-09-17決定の維持）。

## 1. サーバー

### 1.1 起動設定

- AC-SRV-CFG-1: 環境変数 `VIEWER_PORT`・`VIEWER_TODO_DIR`・`VIEWER_DATA_DIR` で、ポート・todoファイルの置き場・
  `data/` の置き場を上書きできる。未指定時の既定値は従来どおり（3131 / `viewer/` の親ディレクトリ / `viewer/data`）。
  プロジェクト解決の基準（`PROJECTS_ROOT`）は `TODO_DIR` の親ディレクトリとする。

### 1.2 セッション起動の二重防止（H1）

- AC-H1-SRV-1: `POST /api/session/launch` の処理中（`claude --bg` の完了待ち中）に、同じ `file` と `groupId` の
  組への要求が届いた場合、`claude` を起動せず `409 { "error": "launch in progress" }` を返す。
- AC-H1-SRV-2: 処理の成功・失敗（400/500を含む）いずれの場合も、応答後にはロックが解放され、次の要求を受け付ける。
- AC-H1-SRV-3: 別の `groupId`（または別の `file`）への要求はロックの影響を受けない。

### 1.3 メモのみの保存（C3）

- AC-C3-SRV-1: `POST /api/comments` はコメントを保存するだけで、セッションを起動しない（従来仕様の維持）。

### 1.4 更新検知と読み込み失敗（F4・F6）

- AC-F6-SRV-1: `GET /api/board/version?file=<todoファイル名>` は `200 { "mtimeMs": <todoファイルの更新時刻ms> }` を返す。
  不正なファイル名は400、存在しないファイルは404（`/api/board` と同じ）。
- AC-F6-SRV-2: `GET /api/board` の応答に `mtimeMs`（同上）を含める。
- AC-F4-SRV-1: `GET /api/board` で todo.md の読み込み・解析中に例外が起きた場合、プロセスを落とさず
  `500 { "error": "parse failed", "detail": <メッセージ> }` を返す。400/404 の応答（`error` フィールド）は従来どおり。

### 1.5 Claude Codeのmodel/effort（MS）

- AC-MS-SRV-1: `GET /api/claude-settings` は `200 { "global": { "model", "effortLevel", "modelSettings" }, "override": { "model", "effort" } }`
  を返す。`global` は `~/.claude/settings.json`（環境変数 `VIEWER_CLAUDE_SETTINGS` で上書き可）の値で、読めなければ `null`。
  viewerはこのファイルを書き換えない。`override` の未設定項目は空文字。
- AC-MS-SRV-2: `POST /api/claude-settings` `{ "model", "effort" }` は `data/launch-settings.json` に保存し、保存後の `override` を返す。
  空文字は未設定を表す。`model` は `^[A-Za-z0-9][A-Za-z0-9._\[\]-]{0,63}$`（先頭英数字）、`effort` は `low|medium|high|xhigh|max` 以外なら400。
- AC-MS-SRV-3: `POST /api/session/launch` は `override` の設定済み項目を `--model <model>`・`--effort <effort>` として
  `claude --bg` に渡す（`--resume` 時も同様）。未設定の項目のフラグは付けない。

### 1.6 トークンのAPI換算コスト（CO）

コストはAnthropic API公開単価で換算した概算（USD）であり、実請求額ではない。集計元は Claude Code の transcript
（`~/.claude/projects/**/*.jsonl`、環境変数 `VIEWER_CLAUDE_PROJECTS_DIR` で上書き可）の各応答の `message.usage`。

- AC-CO-SRV-1: 1応答のコストは `入力×in + 出力×out + キャッシュ読込×read + キャッシュ書込5m×in×1.25 + キャッシュ書込1h×in×2`
  （単価はUSD/MTok、`server.js` の単価表）。`usage.speed` が `fast` なら2倍。`cache_creation` の内訳が無い場合は
  `cache_creation_input_tokens` を5mとして扱う。単価表に無いモデルは金額に含めず、トークン数だけ `unpricedTokens` に数える。
  `<synthetic>` は対象外。
- AC-CO-SRV-2: 同じ `message.id` の応答は（ファイルをまたいでも）1回だけ数える。
- AC-CO-SRV-3: `GET /api/costs/monthly` は `200 { "months": [{ "month": "YYYY-MM", "usd", "tokens", "unpricedTokens",
  "byModel": [{ "model", "usd", "tokens" }] }] }` を新しい月から返す。月は応答の `timestamp` をサーバーのローカル時刻で区切る。
  対象は集計元配下の全transcript（サブエージェント分を含む）。
- AC-CO-SRV-4: `GET /api/costs/cards?file=<todoファイル名>` は `200 { "cards": { "<groupId>": { "usd", "tokens", "unpricedTokens" } } }`
  を返す。対象は `data/sessions-*.json` でカードに紐付くジョブの transcript（`linkScanPath`）と、その `subagents/` 配下。
  transcriptをたどれないカードは含めない。不正なファイル名は400。
- AC-CO-SRV-5: `GET /api/sessions`・`GET /api/costs/cards` でジョブの `linkScanPath` を読めたときは、sessionsの該当エントリに
  `transcriptPath` として保存する。
  ジョブが削除された後は `transcriptPath` から集計する（削除前に一度も集計されなかったカードは対象外）。

### 1.7 セッション一覧（SL）

- AC-SL-SRV-1: `GET /api/sessions/all` は `200 { "sessions": [{ "file", "groupId", "name", "jobId", "launchedAt", "state", "tempo", "detail", "updatedAt" }] }`
  を返す。対象は `data/sessions-*.json` の全エントリ（viewerから起動したセッション、完了済みを含む）で、`launchedAt` の新しい順。
  `state` 以降はAC-H5相当の `sessionInfoFor` と同じ値（ジョブが消えていれば `state: "unknown"`、他は `null`）。

### 1.8 レート制限の使用率（RL）

5h/7dの使用率はClaude Codeがステータスラインのstdinにだけ渡す値のため、ステータスライン（`self-work/statusline`）が
`~/.cache/claude-statusline/rate-limits.json`（環境変数 `VIEWER_RATE_LIMITS_PATH` で上書き可）へ書き出したものを読む。
viewerはこのファイルを書き換えない。

- AC-RL-SRV-1: `GET /api/rate-limits` は `200 { "rateLimits": { "fiveHour", "sevenDay", "capturedAt" } }` を返す。
  `fiveHour`・`sevenDay` は `{ "usedPercentage", "resetsAt" }`（`resetsAt` はUNIX秒）または `null`、`capturedAt` は書き出し時刻（ISO 8601）。
  ファイルが無い・読めない場合は `{ "rateLimits": null }`。

### 1.9 セッション分岐（BR）

会話の任意の時点までの履歴を引き継いだ新しいセッションを作る。Claude Code公式の `--fork-session` は会話全体の複製しかできないため、
transcriptの `parentUuid` をたどった部分履歴を新しいセッションIDのtranscriptとして書き出し、それを `--resume` する。

- AC-BR-SRV-1: `GET /api/session/transcript` の各エントリに、元の行の `uuid`（無ければ `null`）を含める。
- AC-BR-SRV-2: `POST /api/session/branch` `{ "file", "groupId", "columnName", "groupTitle", "uuid", "text" }` は、カードに紐付くジョブの
  transcript（`linkScanPath`、無ければ `transcriptPath`）から、`uuid` の行を起点に `parentUuid` を根までたどった行だけを元の順序で取り出し、
  `sessionId` を新しいUUIDに置き換えて同じディレクトリの `<新UUID>.jsonl` に書き出す。元のtranscriptは変更しない。
- AC-BR-SRV-3: 書き出し後、最後の行の `cwd` で `claude --bg <model/effort指定> --resume <新UUID> -n <名前> <指示>` を実行し（指示の文面は
  `/api/session/launch` と同じ形式）、`data/sessions-*.json` の該当カードを新しいジョブ `{ "jobId", "name", "launchedAt", "branchedFrom": { "jobId", "uuid" } }`
  に置き換えて `200 { "launched": true, "jobId", "sessionId" }` を返す。
- AC-BR-SRV-4: 入力不正（`text` 空を含む）は400、紐付くtranscriptが無い／`uuid` が見つからない場合は404、同じカードの起動処理中は409
  （AC-H1-SRV-1のロックを共有）、`claude` の失敗は500。

### 1.10 資料プレビュー（AP）

- AC-AP-SRV-1: `GET /api/session/artifacts?jobId=<id>` は `200 { "artifacts": [{ "path", "kind", "locked", "exists" }] }` を返す。対象は
  ジョブのtranscriptとその `subagents/` 配下で、`Write`・`Edit`・`MultiEdit`・`NotebookEdit` の `tool_use` の `input.file_path`（重複なし、最後に書かれた順の新しい順）のうち、
  拡張子が `.html`/`.htm`（`kind: "html"`）、`.png`/`.jpg`/`.jpeg`/`.gif`/`.webp`/`.svg`（`"image"`）、`.md`（`"markdown"`）のもの。
  ファイル名が `.env` で始まる、またはパスに `secret`・`credential`（大文字小文字無視）を含むものは `locked: true`。jobIdが不正なら400、transcriptが無ければ404。
- AC-AP-SRV-2: `GET /api/session/artifact?jobId=<id>&path=<絶対パス>` は、AC-AP-SRV-1の一覧に載り `locked` でない実在ファイルだけを拡張子に応じた
  `Content-Type` で返す。それ以外は403（ロック・一覧外）または404（ファイルが無い）。HTML・SVGには `Content-Security-Policy: sandbox` を付け、viewerのオリジンで
  スクリプトを実行させない。

## 2. 画面

画面の状態は `localStorage`（キーは `viewer:` 接頭辞）とURLの `#` 以降にだけ保持し、`data/` には保存しない。

### 2.1 見た目の基盤（H3・M1・M8・L1・L2・L3・A1〜A6）

- AC-A1-1: 色は `:root` の役割名変数（背景・面・線・入力枠線・文字の主/副/補助・アクセント・状態の稼働中/待機/完了）で定義し、
  個別セレクタに色を直書きしない（列色の算出を除く）。
- AC-H3-1: 情報を持つ文字（件数・日時・ラベル・補助文・ステータス）は背景に対し4.5:1以上。`--ink-faint` 相当の薄色は
  区切り線などの装飾にだけ使う。
- AC-M8-1: 入力欄・ボタンの枠線は背景に対し3:1以上。
- AC-M1-1: `button,input,select,textarea` はページと同じ `font-family` を継承し、入力欄の文字は13px・行間1.6。
- AC-A2-1: 文字サイズは 12/13/15/18/22px の5段階のみ。`font-family` の先頭は `"Noto Sans JP"`（Webフォントは読み込まない）。
- AC-L3-1: `text-transform: uppercase` を使わず、列名・ディレクトリ名は実表記どおりに表示する。
- AC-A3-1: ダークモードを持つ。既定は `prefers-color-scheme` に従い、ヘッダーの切替で「自動/ライト/ダーク」を選べ、選択は
  `localStorage` に保存される。`color-scheme` もテーマに連動し、ダーク時もAC-H3-1・AC-M8-1を満たす。
- AC-L1-1 / AC-A4-1: 列の色（見出しの点・カード左の帯）は列名のハッシュから決まり、並び順が変わっても同じ列は同じ色。
  8色より多い色相を使う。
- AC-A4-2: 待機中の表示は色だけでなくアイコンと文言（「待機中」）を伴う。
- AC-A5-1: カードは見出し（`###` の親）を薄いサブラベル、本題を太字で表示する。
- AC-A6-1: 稼働中の点は控えめに脈打つ。`prefers-reduced-motion: reduce` では動かない。
- AC-L2-1: カード詳細のタスク追加フォームは左右に余白を持ち、入力欄・ボタンが詳細パネルの端に接しない。

### 2.2 レイアウト・ヘッダー（M2・M4・B1・B2・B3・B5・E1・CC1）

- AC-M2-1: ヘッダーの実高さをCSS変数 `--header-h` に持ち、`ResizeObserver` で更新する。sticky要素（全体コメントパネル等）の
  `top` はこの変数を使い、1024px幅・セッションチップ表示時でもヘッダーの裏に隠れない。
- AC-B1-1: 14日完了数グラフはヘッダー1段目の「今日のカード」の横に小さく表示し、ヘッダーは2段目（グラフ専用の段）を持たない。
  グラフのクリックで日別の件数を示すポップオーバーを開く（Escとポップオーバー外クリックで閉じる）。
- AC-B2-1: 左側パネル（`#globalCommentsPanel`、`aside`）は幅320〜360pxに固定し、ボードが残りの幅を使う
  （ボードの `max-width:560px` をやめる）。
- AC-CC1-1: 左側パネルはClaude Codeとのやり取り用の領域であり、「全体コメント」「新規カード追加」は
  この領域に置かない（右側`board-area`のダイアログ側に置く。AC-CC1-2参照）。セッションカード
  （AC-B7-1）はこの領域に置く。やり取り機能そのもの（対話UI等）の実装は別変更で行う。
- AC-B3-1: ビューポート幅1280px以上では、ボードの列を2〜3列のグリッドで並べる。
- AC-B5-1: ヘッダーの進捗は、カード単位（完了/全体）とタスク単位（完了/全体）の両方を表示する。`#status` に同じ進捗を重ねて出さない。
- AC-MS-1: ヘッダーの「モデル設定」ボタンで `<dialog>` を開き、グローバル設定（model・effortLevel・モデル別effortLevel）を
  読み取り専用で表示する。同じダイアログでviewer起動分のmodel（候補: 未設定/opus/sonnet/haiku/fable、自由入力可）と
  effort（未設定/low/medium/high/xhigh/max）を選んで保存でき、保存失敗はAC-H2-2に従い通知する。
- AC-CO-1: ヘッダーの「コスト」ボタンで `<dialog>` を開き、月ごとのAPI換算コスト（合計USD・モデル別内訳）を表示する。
  「API換算の概算であり実請求額ではない」旨を併記し、`unpricedTokens` が1以上の月はその件数を注記する。
- AC-CO-2: カード詳細のヘッダーに、そのカードのAPI換算コスト（`$x.xx`、紐付くtranscriptが無ければ非表示）を表示する。
- AC-RL-1: ヘッダーに5h・7dの使用率（%）とリセット時刻を表示し、60秒ごとに更新する。`rateLimits` が `null`、または該当ウィンドウが
  `null` なら当該表示を出さない。`resetsAt` を過ぎた値は「リセット済み（未更新）」と表示し、%を出さない。
  `capturedAt` をtitle属性で示す（値はClaude Codeが最後に応答した時点のもの）。
- AC-SL-1: ヘッダーの「セッション一覧」ボタンで `<dialog>` を開き、`/api/sessions/all` の全セッションを新しい順に、状態・名前・起動日時・
  todoファイル名とともに表示する。各行は `<button>` で、押すとセッションログ（AC-H5-1と同じダイアログ）を開く。0件なら「セッションはありません」と表示する。
  返信（AC-CC2-1）は表示中のtodoファイルのセッションだけが対象で、他ファイルのセッションはログの閲覧のみ。
- AC-M4-1 / AC-E1-1: フォーカスモード中は全体コメントパネルを隠し、フォーカス中のカードをヘッダー直下の中央に表示する。

### 2.3 列（M5・M6・B4・B8・C4・F2）

- AC-M5-1: 列見出しに開閉を示すシェブロン（閉: ▸ / 開: ▾）を表示する。
- AC-M6-1: 列の操作ボタンは `summary` の外に置き、列見出しのアクセシブルネームは「列名＋件数」だけになる。
  操作ボタンの `aria-label` は列名を含む（例:「<列名> のコメントをまとめてコピー」）。
- AC-C4-1: 列ごとのコピー・更新は `…` メニュー（1つのボタン＋開いたときだけ出る項目）にまとめ、列あたりのTab停止は
  見出し・`…`・「+」の3つ以下になる。
- AC-C4-2: ボード上部に「すべて開く」「すべて閉じる」がある。
- AC-B4-1: 列見出しに、件数に加えてタスク進捗バー（完了/全体）、稼働中数・待機数、コメント数、先頭の未完了タスク本文（1行省略）を出す。
- AC-B8-1: 初期表示の開閉は設定で「すべて閉じる（既定）」「未完了・稼働中のある列だけ開く」「前回の開閉を復元」から選べ、
  選択は全ファイル共通、（復元用の）開閉状態はファイル単位で `localStorage` に保存する。選択の変更は即座に反映する。
- AC-F2-1: 完了カードのまとまりは「完了（n）」と表示する。全カードが完了した列は見出しに完了表示を出す。

### 2.4 カード・カード詳細（H1・H2・H4・H6・M7・M9・B6・C3・C7・CC1）

- AC-H6-1: タスクのチェックボックスはタスク本文をアクセシブルネームに持ち、本文（行）のクリックでも切り替わる。
  ただし行内のボタン（引用等）のクリックでは切り替わらない。
- AC-M7-1: カード詳細・セッションログ・新規カード追加・全体コメントは `<dialog>` の `showModal()` で開く。
  開いている間Tabは背後へ抜けず、Escで閉じ、閉じると開く前にフォーカスしていた要素へ戻る。
- AC-M7-2: 5秒ごとの再描画でカード・列が作り直されても、再描画前にフォーカスしていたカード（カードIDで識別）にフォーカスを戻す。
  開いているカード詳細・入力中の文字は再描画で失われない。
- AC-C7-1: カード詳細は画面右端から出るパネル（全高・幅480〜560px程度）として表示し、左側にボードが見えたままになる。
- AC-C3-1: カード詳細のコメント欄には「メモ保存」と「Claudeに依頼」の2ボタンがある。「メモ保存」は `/api/comments` だけを呼び、
  セッションを起動しない。「Claudeに依頼」はコメント保存に続けて `/api/session/launch` を呼ぶ。
- AC-CC1-2: 新規カード追加は各列見出しの「+」ボタンから、全体コメントはボードツールバーの「全体コメント」ボタンから、
  それぞれ独立した`<dialog>`を開いて行う。カード詳細を開いた状態でタスク行の「全体へ引用」を押した場合は、
  カード詳細を閉じずに全体コメントの`<dialog>`を上へ重ねて開き、引用テキストを入力欄へ挿入する。
- AC-H1-1: 送信処理中は両ボタンと入力欄を `disabled` にし、押したボタンの文言を「保存中…」／「起動中…」に変える。
  完了・失敗で元に戻る。サーバーが409を返した場合は「このカードは起動処理中です」と通知する（即時の再試行は再び409になるため「再試行」は付けない）。
- AC-H4-1: 入力欄には見えるラベルを置く（新規カード追加:「列（プロジェクト）」「内容」、コメント欄・タスク追加欄も同様）。
  placeholderだけに頼らない。
- AC-M9-1: 「コピー」ボタンは動詞と対象を明示した文言にする（「全カードのコメントをまとめてコピー」「全体コメントをコピー」
  「この列のコメントをまとめてコピー」）。コピー対象が0件のときは `disabled` にし、理由（「コメントがありません」）を併記する。
- AC-B6-1: タスク本文末尾の「→ <絶対パス>」は本文から外して「出典」ボタンに畳み、押すとパスを表示する（コピー可能）。
  本文途中の相対パス参照は本文の一部として残す。コピー用プロンプト・引用挿入には従来どおりパス込みの本文を使う。
  長いコード・パスは折り返してはみ出さない。
- AC-H2-1: 通知は最前面（モーダル・パネル表示中も見える）のトースト1か所に出し、`role="status"`（失敗は `role="alert"`）で読み上げる。
- AC-H2-2: コメント保存・タスク追加・カード追加・チェック切替・並べ替え・セッション起動の失敗は必ず通知し、「再試行」を付ける。
- AC-H2-3: 並べ替え（D&D・キーボード）の保存が失敗（`res.ok` が偽または通信失敗）したら、DOMとクライアント状態を保存前の順序へ戻す。

### 2.5 セッション（H5・B7・F3・F5・CC2・CC3）

- AC-H5-1: セッションカードは `<button type="button">` で、キーボード（Tab→Enter/Space）でセッションログを開ける。
- AC-B7-1: セッションカードは`globalCommentsPanel`（左側aside）に表示し、ヘッダーには置かない。
  確認待ち（待機中）のセッションは「要対応」欄に、稼働中のセッションより上に表示する。待機中が0件なら
  要対応欄を、稼働中が0件なら稼働中欄を出さない。フォーカスモード中は他のボード要素と同様に非表示になる。
- AC-F3-1: セッションログが空のとき、理由（「起動直後でまだログがありません」／「紐付くログがありません」）と「再取得」ボタンを出す。
- AC-F5-1: 待機中セッションがn件（n≥1）のとき `document.title` を `(n) Today Todo` にし、faviconにも件数の目印を出す。0件で元に戻す。
- AC-CC2-1: セッションログダイアログには返信欄（テキストエリア＋「Claudeに依頼」ボタン）がある。送信は
  カード詳細のコメント欄「Claudeに依頼」と同じ経路（`/api/comments`保存→`/api/session/launch`で
  `--resume`起動）を通り、busy状態（入力欄・ボタンのdisabled、文言変化）・409/失敗時の挙動
  （AC-H1-1・AC-H2-2）もカード詳細と共通にする。
- AC-CC2-2: 待機中（blocked）セッションへの返信は、サーバー側が`claude stop`で対象セッションを
  停止してから`--resume`することで、新しいコピーを作らず同一jobIdのまま会話を継続する。返信成功時に
  開いたままのセッションログダイアログは最新のセッション情報へ追従する（同一jobIdのため実質的な
  開き直しやフォーカス移動は起きない）。稼働中（working）セッションへの返信はコメント保存のみに留め、
  その旨をトースト通知する（既存のカード詳細と同じ挙動）。
- AC-BR-1: セッションログのassistantのテキストエントリごとに「ここから分岐」ボタンを置く。押すと返信欄の文を指示として
  `/api/session/branch` を呼び、成功したらそのカードのセッションは分岐先に切り替わる（ログダイアログは閉じる）。返信欄が空なら
  「分岐後の指示を返信欄に入力してください」と通知して何もしない。busy状態・失敗通知はAC-CC2-1と共通。表示中のtodoファイルのセッションのみ対象。
- AC-AP-1: セッションログのヘッダーに「資料」ボタンを置き、そのセッションが書いた資料（AC-AP-SRV-1）の一覧を開く。0件なら「このセッションが書いた資料はありません」。
  `locked` の資料は🔒付きの無効ボタンで表示し開けない。存在しない資料は「削除済み」と表示し開けない。選ぶと同じダイアログ内で、HTMLは `sandbox` 属性付きの
  `iframe`、画像は `img`、Markdownは本文のテキスト（`textContent`、描画なし）で表示する。
- AC-CC3-1: セッションログの直近のエントリが`AskUserQuestion`ツール呼び出しで、かつセッションが
  待機中（blocked）のときは、質問文と選択肢（ラベル）をボタンとして表示する。ボタンを押すと
  返信欄にそのラベルを入れて即座に送信する（経路はAC-CC2-1・AC-CC2-2と同じ）。`multiSelect`の
  質問は対象外とし、従来どおり自由入力のみとする（選択肢ボタンを出さない）。送信中は他の返信欄
  コントロールと同様にボタンをdisabledにする。

### 2.6 キーボード操作（C1・C2・C5・L4）

- AC-C1-1: 入力欄にフォーカスがなく、ダイアログが開いていないとき、次のショートカットが効く:
  `j`/`k` カード移動、`Enter` カード詳細を開く、`x` フォーカス中カードの先頭の未完了タスクをチェック、`/` 検索欄へ、
  `f` フォーカスモード切替、`[`/`]` 全列を閉じる/開く、`?` ショートカット一覧を開く。
- AC-C2-1: すべての複数行入力欄で `Ctrl+Enter`（macは `Cmd+Enter`）が既定の送信ボタンを押したのと同じ動作になり、欄の近くに案内を出す。
  カード詳細のコメント欄の既定は「メモ保存」。
- AC-C2-2: 「Claudeに依頼」ボタンを持つ入力欄（カード詳細のコメント欄・セッションログの返信欄）では、修飾キーなしの `Enter`（IME変換中を除く）が
  「Claudeに依頼」と同じ動作になり、`Shift+Enter` で改行する。
- AC-C5-1: フォーカス中のカードで `Alt+↑`/`Alt+↓` を押すと列内で1つ上/下へ移動して保存され、フォーカスはそのカードに残る。
  カードの操作メニューにも「上へ」「下へ」がある。

### 2.7 検索・絞り込み・URL（D1・D2・D3・L5）

- AC-D1-1: ヘッダーの検索欄への入力で、カード名・タスク本文に一致するカードだけを表示し、一致箇所を強調し、一致のある列を自動で開く。
  空にすると元の表示（開閉状態を含む）に戻る。
- AC-D2-1: 絞り込みチップ「未完了のみ」「コメントあり」「稼働中」「待機中」「今日追加」を持ち、複数選択はAND。検索と併用できる。
  「今日追加」は、`/api/files` の一覧で表示中ファイルの1つ前の日付のファイルに同じカードID（`id`）が無いカードを指す。
  1つ前のファイルが無い場合はチップを出さない。
- AC-D3-1: 表示中ファイル・開いている列・フォーカスモード（とその対象）・開いているカードをURLの `#` 以降に反映し、
  再読み込みやURL共有で同じ状態を復元する。`#` の情報が不正・古い場合は無視して通常表示にする。

### 2.8 フォーカスモード（M3・E2〜E5）

- AC-E5-1: フォーカス対象として、各列に加え「全列の未完了」「★を付けたカード」を選べる。★はカード詳細とカード上のボタンで付け外しでき、
  `localStorage` にファイル単位で保存する。
- AC-E3-1: 「後で」はそのカードを今回のフォーカスの並びの最後に回す（保存しない。フォーカスモードを抜けると元の並び）。
  「次へ」は並びを変えず次へ進む。
- AC-M3-1 / AC-E2-1: 終了画面は、対象の未完了が0件なら「すべて完了しました」、未完了が残ったまま一巡したら「一巡しました（未完了n件）」
  と出し分け、後者には「もう一周」を置く。
- AC-E4-1: フォーカスモード中（入力欄外）は `→` 次へ、`Space` 先頭の未完了タスクをチェック、`Esc` カンバンへ戻る。

### 2.9 空状態・読み込み（F1・F4・F6）

- AC-F1-1: 全体コメントが0件のとき、全体コメントの`<dialog>`内に用途の説明と
  「カード詳細の『全体へ引用』で参照を挿入できる」旨を表示する。
- AC-F4-1: ボードの読み込み失敗時は、理由（HTTPステータスとサーバーの `error`、通信失敗なら「サーバーに接続できません」）と
  「再試行」ボタンを表示する。
- AC-F6-1: 表示中のtodo.mdが外部で更新されたら（`/api/board/version` の `mtimeMs` が読み込み時と異なる）、自動では差し替えず
  「新しい内容があります」と「再読込」を通知する。確認間隔は既存の5秒更新に合わせる。
